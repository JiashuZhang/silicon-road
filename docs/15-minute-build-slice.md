# 《硅之路》15 分钟飞轮危机局

> **文档状态（2026-09）**：唯一玩法规范。当前开发里程碑是 6 个经营回合加 1 个最终危机的灰盒；灰盒通过 Gate 后才扩展为 12 回合、约 15 分钟的正式切片。现有 Web 原型仅用于复用视觉、题材和左右二选一交互，旧流程与旧数值不构成实现约束。

## 一、产品承诺

玩家在 9 个经营回合内组装一台公司增长引擎，让知识、客户网络或生产规模产生复利，然后用这套 Build 扛过 1982 年的三阶段科技寒冬。

完整体验必须同时成立：

```text
简单操作
  ↓
明确目标
  ↓
每次选择立即反馈
  ↓
能力组成 Build
  ↓
Build 产生指数成长
  ↓
随机市场迫使玩家调整
  ↓
三阶段危机检验公司
  ↓
结局解释成败并推动重开
```

本模式不依靠大量剧情牌维持时长。核心乐趣来自构筑、触发、增长、取舍和验证。

## 二、当前灰盒与目标版本

当前不直接制作完整 12 回合版本。先用 7 个回合验证 Build 差异、能力替换和重开欲望。

| 灰盒阶段 | 回合 | 内容 |
| --- | ---: | --- |
| 建立方向 | 1—3 | 看见一条完整 Build 路径，但可以主动拒绝或混搭 |
| 驾驶 Build | 4—6 | 随机机会、一次市场事件、跨路线组件与槽位取舍 |
| 最终检验 | 7 | 一场同时检查 Build 形态和资源短板的危机 |

灰盒预计首局 6—10 分钟。只有四项核心假设全部通过，才扩展为以下目标版本：

| 阶段 | 回合 | 目标时间 | 内容 |
| --- | ---: | ---: | --- |
| 建立方向 | 1—3 | 3 分钟 | 选定路线并保证看见一条完整飞轮路径 |
| 扩张与调整 | 4—6 | 4 分钟 | 随机机会、第一次市场冲击、能力槽取舍 |
| 危机准备 | 7—9 | 4 分钟 | 放大 Build 或补足防线，锁定最终公司形态 |
| 科技寒冬 | 10—12 | 3—4 分钟 | 价格崩塌、融资冻结、保护核心 |

灰盒界面始终显示：

- 当前回合，例如 `4 / 7`；
- 距离最终危机还有几回合；
- 胜利目标：塑造一套能通过最终危机的公司引擎；
- 当前四项资源和六个能力槽；
- 当前路线专属状态：未发布知识、有效客户与待交付合同，或库存与下一市场窗口。

## 三、30 秒核心循环

每个经营回合执行以下步骤：

1. 展示 3 个随机机会。
2. 玩家选择 1 个机会。
3. 进入一张左右二选一卡牌，决定处理方式。
4. 立即结算资源变化，并安装、替换或失去一项能力。
5. 若本次行动推动了 Build，立即执行该 Build 独有的蓄力、连击或库存规则。
6. 市场时钟前进，展示下一回合机会。

玩家的操作只有：

- 点击一张机会；
- 点击或左右滑动选择处理方式；
- 能力槽已满时，点击一个旧能力进行替换。

不设置背包、地图、工人摆放、复杂科技树或多层菜单。

## 四、前三分钟留存脚本

前三回合不是完全随机，而是根据玩家的选择动态发牌。系统保证玩家看见通向飞轮的路径，但不保证替玩家完成飞轮。

### 回合 1：选择基础

同时出现三个方向：

- 自研团队：进入技术先锋路线；
- 企业客户：进入客户机器路线；
- 自有产线：进入韧性制造路线。

玩家在 20 秒内完成第一次选择，并立即获得资源变化和第一个能力。

### 回合 2：选择引擎

三个机会包含：

- 1 个与首个能力匹配的引擎；
- 1 个其他路线的基础能力；
- 1 个解决当前资源短板的普通行动。

界面明确显示匹配引擎将连接哪一项已有能力。

### 回合 3：首次兑现

若前两回合选择了匹配的基础和引擎，三个机会包含：

- 1 个完成当前 Build 的兑现能力；
- 1 个高额短期收益；
- 1 个跨路线能力。

若玩家此前拒绝匹配路线，则第三回合改为提供：补回原路线的机会、形成临时跨路线协同的机会，以及高额即时收益。三种选择都必须说明自己放弃了什么。

只有玩家主动选择兑现能力后，才以独立结算画面演示路线的核心动作：技术完成第一次发布，客户获得第一笔续约，制造完成第一次备货与交付。画面必须说明今后的持续规则和主要风险。

前三分钟验收条件：玩家已经做出三次有效选择、完成或主动拒绝一套 Build，并看见至少一次可解释的复利反馈。

## 五、资源与失败

保留四项公开资源：

| 资源 | 作用 | 归零结果 |
| --- | --- | --- |
| 资金 | 支付研发、生产和危机成本 | 公司破产 |
| 技术 | 支撑产品差异化和技术变现 | 产品失去竞争力 |
| 人才 | 支撑研发、交付和生产 | 团队解体 |
| 市场 | 代表客户、渠道和品牌位置 | 公司失去订单 |

普通选择显示变化方向，不显示精确数字；结果页立即显示实际数字。任何资源归零都会立刻结束本局，并解释最近两项相关决策。

资源负责限制玩家，能力和飞轮负责产生增长。单纯堆高资源不能获得 Build 结局。

### 灰盒资源经济表

第一轮测试使用小数值，优先验证取舍是否可读，不追求最终平衡。

| 项目 | 灰盒基准 |
| --- | ---: |
| 四项资源初始值 | 各 8 |
| 四项资源上限 | 各 20 |
| 普通行动主要收益 | `+2` 或 `+3` |
| 普通行动主要成本 | `-1` 至 `-3` |
| 市场事件基础损失 | `-2` 至 `-4` |
| 最终危机基础损失 | 两项资源各 `-4` |
| 健康终局区间 | 每项资源 4—12 |

增长采用指数感知而非严格指数。各路线的四个成长阶段统一使用规模档位 `2 / 4 / 7 / 11`，但这些数字分别代表知识、客户价值或库存数量，不直接等于资源增量。这样既能让玩家感到越转越快，又不会让单次 `+16` 摧毁小数值经济。

### 致命预警与断臂求生

只要某个选项在最坏的公开结果下可能让资源归零，选项旁必须显示：

> **致命风险：该选择可能让人才归零，公司将立即倒闭。**

每局第一次归零时，玩家可以牺牲一个永久能力，将该资源恢复到 1。每局只能使用一次；没有能力可牺牲或第二次归零时立即失败。这个机制必须记录被牺牲的能力，并在结局中说明它如何破坏或改变了 Build。

## 六、能力槽与 Build

公司只有 6 个永久能力槽。开局的“办公室租约”占用其中一槽，拆除它需要支付 1 资金违约金；因此持续安装能力的玩家会在灰盒结束前至少经历一次替换。获得新能力且槽位已满时必须替换一个旧能力，新能力安装后立刻重新计算 Build。

每套 Build 由三种组件组成，但组件完成后不会启动同一种“做同色牌加同色资源”规则：

- **基础**：决定公司从哪里起步；
- **引擎**：决定哪类行动可以持续放大；
- **兑现**：把积累转化为可以生存的收入或市场位置。

### 技术先锋

| 组件 | 能力 | 作用 |
| --- | --- | --- |
| 基础 | 自研团队 | 研究时积累知识，暂时不产生收入 |
| 引擎 | 先进实验室 | 每次研究使下一次研究额外增加知识 |
| 兑现 | 自主产品 | 主动“发布”，消耗全部知识换取产品收入和市场 |

**核心动词：研究 / 发布。**

技术路线是延迟兑现的蓄力玩法。连续研究会让知识沿 `2 → 4 → 7 → 11` 增长，但研究期间持续消耗资金，且不会自动带来市场。玩家必须判断何时停止研究并发布：过早发布收益太低，过晚发布可能在融资冻结前破产。发布后知识归零，但保留实验室等级。

主要失败方式：一直研究却没有产品；为了续命过早发布；技术换代事件使尚未发布的部分知识贬值。

### 客户机器

| 组件 | 能力 | 作用 |
| --- | --- | --- |
| 基础 | 企业客户 | 可以签下一份持续占用交付能力的合同 |
| 引擎 | 销售网络 | 连续成功交付会让下一份合同价值翻倍 |
| 兑现 | 长期合同 | 每回合自动收入，但必须按时支付人才完成交付 |

**核心动词：接单 / 交付。**

客户路线是不能中断的连击玩法。连续交付使合同网络价值沿 `2 → 4 → 7 → 11` 增长，并在每回合自动产生收入。接新单会提高未来收入，却占用下一回合的交付能力；若玩家转去做其他事情、人才不足或主动毁约，连击归零并损失市场。

主要失败方式：订单超过团队产能；为保持连击忽略技术；单一大客户取消合同时引发连锁违约。

### 韧性制造

| 组件 | 能力 | 作用 |
| --- | --- | --- |
| 基础 | 自有产线或稳定代工 | 决定固定成本和每批可生产数量 |
| 引擎 | 流程控制 | 连续生产同一产品时批量成本下降 |
| 兑现 | 战略库存 | 在市场事件到来前生产库存，事件发生时统一出售 |

**核心动词：生产 / 出货。**

制造路线是预测未来的库存玩法。玩家根据提前公开的市场事件决定生产规模，库存沿 `2 → 4 → 7 → 11` 增长，单位成本随规模下降。库存不直接产生收益，只有在订单潮、短缺或危机中出货才兑现；需求不足时，每批库存都会占用资金并承担减值。

主要失败方式：押错需求造成库存堆积；产能扩张锁死现金；为了短期出货错过更高价值的短缺窗口。

## 七、三种增长引擎

三套 Build 都能产生指数成长，但增长对象、兑现时机和中断条件不同。

| Build | 增长对象 | 如何增长 | 如何兑现 | 如何中断 |
| --- | --- | --- | --- | --- |
| 技术先锋 | 未发布知识 | 连续研究：`2 → 4 → 7 → 11` | 玩家主动发布，知识清零 | 发布或技术贬值 |
| 客户机器 | 客户网络价值 | 首次签约建立 `2` 点基础价值；连续交付推进至 `4 → 7 → 11` | 每回合自动收入 | 断交、毁约或人才不足 |
| 韧性制造 | 库存数量 | 连续生产：`2 → 4 → 7 → 11` | 在市场窗口主动出货 | 出货、减值或更换产品 |

这些数字表示各路线专属状态的规模，不直接等于某项资源加成。最终资源收益还要受到发布质量、合同利润率或市场需求影响。

每条路线必须有一个明确的“继续贪还是现在兑现”问题：

- 技术玩家决定是否再研究一次；
- 客户玩家决定是否接下超过当前交付能力的合同；
- 制造玩家决定是否在需求尚未确定时继续生产。

增长必须通过以下反馈同时表现：

- 能力槽连线和依次点亮；
- 路线专属状态发生变化，例如知识翻倍、合同续约或库存入库；
- 兑现时播放对应资源动画；
- 一句说明本次由哪些能力共同产生增长，以及何时才能兑现；
- 下一批机会至少有一张受到该飞轮影响。

拆除核心组件后，该路线立即按自身规则处理未兑现资产：知识可能流失、合同可能违约、库存可能减值。重新补齐组件不会无条件恢复原进度。

## 八、能力语义与组合空间

每项能力在配置中必须定义以下字段：

| 字段 | 含义 |
| --- | --- |
| 名称与类别 | 核心组件、强化件、跨路线件或防御件 |
| 安装效果 | 获得时立即发生的变化 |
| 持续效果 | 留在槽位期间持续修改的规则 |
| 触发条件 | 哪个动作或市场事件会触发 |
| 组合关系 | 与哪些能力或状态产生额外作用 |
| 替换损失 | 被拆除时知识、合同或库存如何处理 |
| 危机用途 | 在最终危机中提供哪个条件或牺牲选项 |

若一项能力只提供一次资源增减、不会改变后续选择，它不是能力，只能作为普通行动结果。

### 首批 6 个跨路线能力

| 能力 | 连接路线 | 规则变化 | 代价 |
| --- | --- | --- | --- |
| 技术授权 | 技术 + 客户 | 发布时可保留一半知识，并按有效客户数获得资金 | 产品市场收益减半 |
| 联合开发 | 客户 + 技术 | 成功交付后视为一次低级研究 | 每次额外消耗 1 人才 |
| 定制芯片 | 客户 + 制造 | 有待交付合同时，生产直接锁定一部分需求 | 失去面向公开市场的高价窗口 |
| 柔性产线 | 制造 + 技术 | 技术换代时可花 2 资金更换库存产品，不清空批量等级 | 每次切换消耗 1 人才 |
| 预售生产 | 技术 + 制造 | 发布前可按知识规模预售，所得资金只能用于生产 | 发布失败时同时损失市场 |
| 售后网络 | 制造 + 客户 | 出货后增加交付能力，允许多维持一份合同 | 每回合固定消耗 1 资金 |

跨路线能力必须改变一种状态向另一种状态的转换，不能只写“两条路线同时获得 +2”。玩家应能主动发现并复述具体组合，例如“联合开发让交付顺便推进研究”。

### 构筑原型清单

六个槽位必须支持以下形态，且没有一种在所有市场事件下占优：

| 构筑 | 槽位结构 | 优势 | 风险 |
| --- | --- | --- | --- |
| 单路线专精 | 3 核心 + 2 强化 + 1 防御 | 路线状态成长最快 | 被针对时难以转向 |
| 双引擎 | 两套 3 核心 | 两种基本循环 | 缺少强化与防御，资源互相争夺 |
| 混合公司 | 3 核心 + 2 跨路线 + 1 防御 | 状态转换灵活 | 单项峰值较低 |
| 玻璃大炮 | 3 核心 + 3 强化 | 兑现上限最高 | 无致命风险缓冲 |
| 稳健幸存 | 3 核心 + 3 防御 | 危机容错高 | 难以达到爆发结局 |

双引擎不能自动成为最优解：第二套 Build 的固定成本必须照常支付，且同一回合只能执行一个核心动作。

## 九、机会与随机性

第 4—9 回合使用带种子的随机机会池。每回合的三张牌由三类机会组成：

1. **延续**：推动当前 Build 的下一步动作，例如研究、交付或生产；
2. **应对**：解决当前最低资源或下一次公开市场事件；
3. **诱惑**：来自另一条 Build 的高收益能力。

三张牌的位置每回合随机。若某类没有合法机会，则从通用机会池补充。

随机性只决定玩家面对什么问题，不随机篡改已经作出的决定：

- 每局生成并保存一个种子；
- 相同种子产生相同机会和市场事件；
- 卡牌结果在选择前可预览方向；
- 点击后不进行隐藏成功率判定。

第 4、6、8 回合各发生一次市场事件，并提前一回合预告：

- 订单潮：客户行动增强，人才消耗增加；
- 芯片短缺：制造能力增强，无供应能力者损失市场；
- 融资收紧：所有高成本行动更加危险；
- 技术换代：技术行动增强，旧产品降低市场；
- 价格竞争：即时现金机会增强，库存价值下降。

市场事件必须同时改变至少两条 Build 的相对价值，不能只给单一路线发奖励。

同一张市场事件对不同 Build 必须提出不同问题。例如“芯片短缺”不是分别给三条路线加不同资源：技术路线考虑是否提前发布不成熟产品，客户路线考虑放弃哪些合同，制造路线决定现在出货还是继续囤货。

### 两层选择的职责

机会层回答“本回合处理什么问题”，二选一卡牌回答“用什么代价处理”。如果第二层只是“安装能力 / 不安装能力”，应合并为一次选择。

二选一必须使用以下至少一种真实对立：

- 短期现金 / 长期能力；
- 稳健小收益 / 激进高风险；
- 专精当前路线 / 转入混合路线；
- 自主控制 / 外部合作；
- 立即兑现 / 继续积累；
- 效率 / 韧性。

两个选项必须都有明确适用场景。若不考虑当前状态时仍有一项全面优于另一项，该卡牌不能进入灰盒。

## 十、高频反馈规范

一次选择必须在 300 毫秒内开始反馈，并依次回答四个问题：

1. **我付出了什么？** 显示资源减少。
2. **我获得了什么？** 显示资源和新能力。
3. **它连接了什么？** 高亮 Build 中已连接与缺失的组件。
4. **它改变了以后什么？** 显示知识、合同或库存状态，以及规则变化或新机会。

普通结算最多展示三行核心信息。首次完成 Build、增长阶段升级、兑现和能力替换可以使用独立强反馈画面。

任何标签或计数都必须带语义：禁止使用没有解释的 `0/3`、内部标签名或只写“协同已触发”。

## 十一、最终危机判定

灰盒只制作一场“订单冻结”危机，用它验证路线差异和混合构筑。目标版再扩展为 1982 年三个危机回合。

### 灰盒危机矩阵

危机先造成基础损失：资金 `-4`、市场 `-4`。玩家必须同时满足一个**业务条件**和一个**生存条件**才能完全解决。核心 Build 最多提供业务条件，不能自动通关。

| 路线形态 | 业务条件 | 生存条件 | 可选牺牲 | 部分解决结果 |
| --- | --- | --- | --- | --- |
| 技术 | 已发布质量至少 7，或拥有技术授权 | 支付 3 资金且人才至少 4 | 清空未发布知识，抵消 2 点资金损失 | 产品仍有竞争力，但研发停摆 |
| 客户 | 至少 3 个仍履约客户，或拥有售后网络 | 人才至少 6 且没有待交付违约 | 主动放弃一半客户，抵消 2 点市场损失 | 保住现金流，但连击归零 |
| 制造 | 在库产品匹配需求，或拥有柔性产线 | 支付库存持有成本后资金至少 3 | 清仓全部库存，抵消 2 点资金损失 | 工厂存续，但批量等级归零 |

判定结果：

- 两个条件都满足：完全解决，获得生存印章；
- 只满足一个条件：部分解决，执行对应代价后继续；
- 两个条件都不满足：承受全部损失，并允许使用一次断臂求生；
- 结算后任一资源归零且无法断臂：立即失败。

灰盒必须测试同一 Build 的至少三种形态：高成长低资源、低成长带防御、加入跨路线转换。若三者在危机中的答案相同，危机设计失败。

### 目标版：1982 年科技寒冬

经营阶段结束后固定进入三个危机回合。危机不再发放普通能力，只检验玩家已经建成的公司。

### 回合 10：价格崩塌

- 技术先锋必须决定立即发布现有知识，还是保留下一代产品并承受现金损失；
- 客户机器必须在维护合同连击和主动放弃低利润客户之间选择；
- 韧性制造必须决定清仓止损，还是赌下一阶段短缺再出货。

### 回合 11：融资冻结

- 技术先锋只能出售已发布技术，未发布知识不能直接抵押；
- 客户机器按仍在履约的有效客户数获得预付款，违约客户不计入；
- 韧性制造可以抵押产能，但库存越高，银行给出的折价越严重。

### 回合 12：保护核心

玩家只能保护一套 Build。被保护的完整 Build 提供最终解决方案，其他能力承担明确损失。

每解决一个危机获得一枚“生存印章”。

## 十二、结局与重开

### Build 爆发

灰盒同时满足：

- 至少一套 Build 完整；
- 完全解决唯一危机；
- 四项资源均大于 0；
- 技术完成过质量至少 7 的发布、客户维持过至少三连交付，或制造在匹配窗口完成过批量出货。

目标版同时满足：

- 至少一套 Build 完整；
- 获得至少 2 枚生存印章；
- 四项资源均大于 0；
- 最终保护了完整 Build；
- 技术完成过高质量发布、客户维持过至少三连交付，或制造在正确窗口完成过批量出货。

### 勉强幸存

公司没有倒闭，但不满足 Build 爆发条件。结局说明公司失去了什么以及为什么只能维持生存。

### 公司倒闭

任一核心资源归零。结局必须列出直接死因和导致它的最近两次决策。

结算页固定展示：

- 最终公司类型；
- 路线专属成绩：最高知识与发布质量、最长交付连击与有效客户数，或最大库存与出货利润；
- 三项形成 Build 的关键决策；
- 一项导致损失或崩溃的关键决策；
- 本局错过的一个关键机会；
- 本局种子。

结算页提供两个同等显著的按钮：

- **相同市场重试**：保持种子，允许玩家验证不同选择；
- **生成新市场**：使用新种子，检验 Build 的适应能力。

不设置永久数值加成。重开的动力来自理解、路线差异和随机市场，而不是局外刷取。

## 十三、灰盒内容预算

首个可测版本只制作：

- 6 个经营回合和 1 个危机回合；
- 3 套 Build，每套 3 个核心组件；
- 6 个跨路线或强化组件；
- 12 张经营机会；
- 2 种市场事件；
- 1 张危机牌；
- 3 个 Build 爆发结局；
- 1 个幸存结局；
- 4 个资源归零失败模板。

暂不制作：

- 1960—2030 完整年代；
- 逐年经营；
- 第二时代；
- 角色好感系统；
- 复杂科技树；
- 局外成长；
- 多层卡牌品质；
- 依靠大量剧情牌延长时长的内容。

## 十四、实现顺序

现有原型不继续增量修补。重做顺序如下：

1. 新建 7 回合灰盒状态机和带种子的随机数生成器。
2. 实现六能力槽、安装和替换。
3. 分别实现知识蓄力、合同连击和库存窗口三套状态机，不共享统一倍率结算器。
4. 制作前三回合动态引导牌。
5. 制作第 4—6 回合机会生成器和市场事件。
6. 实现灰盒危机矩阵与三档结局。
7. 接入视觉反馈、复盘与两个重开入口。
8. 最后再迁移可复用的旧卡牌文本。

## 十五、验证 Gate

邀请 10 名不了解半导体的玩家独立试玩，不解释规则。首轮只测试 7 回合灰盒；通过后再测试 12 回合目标版。

| 指标 | 通过标准 |
| --- | --- |
| 10 秒目标理解 | 至少 8 人能说出“造出公司引擎并活过科技寒冬” |
| 20 秒首次行动 | 至少 8 人完成第一次有效选择 |
| 3 分钟飞轮反馈 | 至少 8 人看见第一次飞轮，至少 6 人能解释为何触发 |
| 5 分钟 Build 认知 | 至少 7 人能说出自己的三个核心组件和主要风险 |
| 增长感知 | 至少 7 人理解自己路线的状态为何产生复利，以及何时兑现 |
| Build 区分 | 至少 7 人能在不提颜色和资源名称的情况下，说出三条路线的操作差异 |
| 随机应变 | 至少 6 人因市场事件改变一次原计划 |
| 失败可解释 | 至少 7 人能说出直接死因和一项历史原因 |
| 灰盒完成 | 至少 8 人在 6—10 分钟完成首局 |
| 决策犹豫 | 每位玩家至少有 2 次比较选项超过 5 秒，且能说明取舍 |
| 主动归因 | 至少 6 人未经提示便把结果归因到自己的某次选择 |
| 组合表达 | 至少 4 人主动描述一个跨路线组合，而非只说资源高低 |
| 主动重开 | 至少 5 人无需邀请便开始第二局 |
| 重开策略变化 | 重开玩家中至少一半改变 Build 或关键决策 |

测试同时记录首局和第二局的总时长、阅读时间、决策时间与结算观看时间。不得为了达到 15 分钟加入强制等待或增加说明文字。

若“3 分钟飞轮反馈”未通过，停止增加内容并重做前三回合。若“Build 区分”或“组合表达”未通过，不扩写机会数量，先重做能力规则。若“主动重开”未通过，优先检查随机市场、Build 差异和结局复盘，不增加剧情长度。

### 防换皮检查

每次新增或调整 Build 后执行以下检查：

1. 隐去路线名称、颜色和资源图标，只保留规则文本。
2. 比较面对同一机会时三条路线的最佳选择和最佳时机。
3. 若三条路线都倾向于“连续选择同类牌直到倍率最高”，该版本判定失败。
4. 合格版本必须分别产生“再蓄力还是发布”“续约还是断开连击”“现在出货还是继续囤货”三个不同问题。
