# 卡牌配置说明

全部固定卡牌、条件卡牌和经营卡牌内容位于根目录的 `cards.config.js`。修改卡牌时不需要改动 `app.js`。

## 固定卡牌

`cards` 保存普通剧情牌。每张牌包含：

- `year`：显示年份，也用于随机卡牌按时间排序。
- `type`：卡牌类型，对应界面的类型名称。
- `title`：标题。
- `body`：正文。
- `choices`：选项列表。

每个选项由 `choice()` 创建，参数依次为：

1. 选项文字。
2. 数值变化。
3. 结算标题。
4. 结算正文。
5. 新增标签。
6. 移除标签。
7. 可选的显示条件。
8. 可选的经营结算数据。

数值键包括 `cash`、`tech`、`talent`、`market` 和 `reputation`。标签用于后续条件卡、危机结算、营收修正和胜利判定。

调整选项数值时，以所有数值变化的数学和作为第一层平衡检查：普通选项尽量控制在 `-1—+1`。高价值战略可以提供较大的单项回报，但应同时配置相应的现金投入、机会成本或其他属性损失，避免出现无代价的高净正收益。危机和明显错误的决策可以保留更大的净负值。

## 条件卡牌

`conditionalCards` 保存根据旧选择变化的卡牌。目前包括：

- `E10`：根据是否拥有自有工厂选择版本。
- `P02`：根据沈岚是否仍在公司选择版本。

每组必须提供 `default` 版本。新增条件卡时，还需在 `app.js` 的 `getCard()` 中声明使用哪个标签选择版本。

## 经营卡牌

`management` 保存：

- 六次经营结算的年份。
- 经营卡标题与正文。
- 研发、市场和现金三种预算方案；每张经营卡按顺序轮换其中两个方案供玩家选择。

`budgetCost` 是专项支出；`effects` 是专项选择产生的非现金变化。营业收入与运营成本由引擎在第三次公司决策后的年报中统一结算，不属于经营卡牌配置。`budgetCost` 因而只扣除该方案的额外专项预算，避免同一年重复计算经常性收支。

`companyActions` 保存通用公司行动的基础数值与随机规则：

- `variance.normal`：普通年份逐属性修正区间，当前为 `-5—+5`。
- `variance.crisis`：经济危机逐属性修正区间，当前为 `-7—+3`。
- `variance.crisisYears`：使用危机区间的年份。
- `actions`：九项公司行动的基础效果；“接普通订单”的资金基础值为 `+10`。
- `defaultVarianceCopy`：各属性通用的正向、负向波动文案。
- `actionVarianceCopy`：特定行动覆盖通用文案，例如普通订单的回款、人才和市场反馈。

经营方案通过 `actionId` 选择文案组。随机数只在玩家确认行动时生成，结果与文案随后进入存档，不会因刷新而改变。

## 年度决策与外部事件

`annual` 控制 1960—2001 年的年度回合：

- `decisionsPerYear`：每年公司决策数量，当前为 3。
- `timeline`：固定历史牌、危机牌、经营牌和三条路线牌出现的年份。
- `decisionCards`：用于补足年度决策的随机卡池。
- `externalEvents`：每年第一张外部事件的随机卡池；1982 与 2001 年由年末危机结算取代。

年度决策使用 `category` 区分 `competitor`、`supply`、`personnel` 和 `governance`。生成器优先保证同一年抽到不同类别，并在牌池耗尽前避免重复。

外部事件使用 `defaultOutcome` 定义默认结果，使用 `variants` 根据长期标签替换结果。这样，同一项产业新闻可以对持股者形成收益，也可以对公开竞争者造成市场与声誉打击。

外部事件可选用 `marketMultiplier: { minimum, maximum }` 约束当年行情。只应为明确描述宏观周期的事件配置该字段，例如衰退事件使用 `0.5—0.9`、繁荣事件使用 `1.1—1.5`；其他事件仍在全局范围内随机。

`balance.economy` 集中配置年度经营公式，包括收入基础值、能力除数、声誉基准、年度行情随机范围、人才成本率、人才流失和技术演进参数。`marketFluctuation` 控制每年 `0.5—1.5` 的随机行情系数并先调整市场值；`annualChange.talentMarketPressureBase` 和 `talentMarketPressureDivisor` 再把当前市场线性换算为人才压力。标签不参与年度数值公式，只用于后续卡牌、路线、危机和结局条件。

`minYear` 和 `maxYear` 可以限制随机卡牌出现的年代。不填写时，卡牌在整个时间线内有效。

## 难度配置

`balance.victory` 集中保存终局门槛：

- `minimumStats`：资金、技术、人才、市场的最低值。
- `minimumReputation`：隐藏声誉最低值。
- `resilienceTags`：组织韧性标签列表。
- `minimumResilience`：至少需要获得多少个韧性标签。

终局成功还要求当前路线的四个里程碑全部完成、危机中保护核心，并且没有委员会化或放弃长期战略。

修改配置后直接刷新 `index.html` 即可生效。年度结构发生变化时，旧存档会自动失效，避免旧序列掩盖新增卡牌。
