# 《硅之路》轻量经营系统

> **文档状态（2026-09）**：资源职责与数值公式仍可作为调参参考；“每个自然年四张牌”及旧时长目标描述的是已停用的旧流程。新游戏默认进入 [《硅之路》15 分钟 Build 垂直切片](15-minute-build-slice.md)。

## 一、设计目标

经营系统用于回答两个问题：玩家即使看对了未来，是否有足够的现金等它到来；玩家是否愿意为了未来效率，牺牲眼前的生存空间？

系统借鉴生存游戏的资源循环：取得基础资源、维持消耗、制造提高效率的工具、争取高价值机会，并在可预期的危机到来前完成准备。借鉴的是循环和时间压力，不是把采集、战斗、烹饪逐项替换成公司术语。

它不会发展成完整财务或库存模拟。游戏不单独管理贷款利率、原材料数量、工资名单或股价，而是使用四项常驻数值、少量资产标签和限时机会表达经营状态。

## 二、现有原型的年度回合（待替换）

每个自然年包含四张牌：

1. 一张年初随机外部事件牌，读取公司此前积累的标签并立即结算。
2. 三张公司决策牌，覆盖竞争、供应链、人员和治理。

外部事件先建立当年的经营背景，避免打断公司选择与其结果之间的因果反馈。第三次公司决策完成后，先单独显示该次决策的结果；翻页后再结算营业收入与运营成本，并显示独立的当年年报，随后进入下一年。这次结算不占用卡牌名额；刷新或从存档继续时不会重复结算。1982 与 2001 年以危机取代普通外部事件，仍遵循“第三次决策结果—当年年报—危机”的特殊顺序。

六张专项预算牌仍会在指定年份占用一个公司决策名额。它们只决定研发、市场或现金保留等专项预算，不重复计算当年的营业收入与运营成本：

- 1967 年。
- 1971 年。
- 1977 年。
- 1981 年。
- 1989 年。
- 1998 年。

固定剧情牌、路线牌和危机牌同样占用公司决策名额。因而每年始终保持三次主动选择，不会因为关键剧情额外膨胀。

## 三、资源循环

四项常驻数值承担不同职责：

- **资金**是生存倒计时，用于支付每期运营成本和所有主动投资。
- **技术**是项目能力，决定能够研发哪些产品；不持续投入时会相对时代落后。
- **人才**是执行能力，不等于员工人数；高强度项目会消耗它，招聘和培训可以恢复它。
- **市场**是订单与渠道，决定基础收入和产品变现能力；长期没有产品或推广会逐渐衰减。

循环关系为：

```text
合同产生资金，但占用人才
资金购买设备、招聘和培训
设备与人才提高研发效率
技术解锁产品和市场机会
市场与声誉带来更好的合同
运营成本、技术过时和机会期限持续施加压力
```

除常驻数值外，只增加两类轻量状态：

- **资产标签**：仪器、工厂、设计工具、核心人才等。标签用于解锁后续选项、事件变体、路线和危机判断，不在年末自动重复增加或扣除数值。
- **限时机会**：订单、人才候选人和市场窗口。机会保留一至三个经营周期，过期后离开。

不加入可自由堆叠的零件仓库。玩家管理的是公司能力和机会顺序，而不是整理几十种材料。

## 四、公司行动与初始数值

以下数值是第一轮原型标尺，不是最终平衡结果。四项常驻数值范围为 `0—100`，初始值均为 `50`。

| 行动 | 基础变化 | 持续效果或代价 |
| --- | --- | --- |
| 接普通订单 | 资金 `+10`、人才 `-4`、市场 `+2` | 可能建立客户标签 |
| 加大研发 | 资金 `-8`、技术 `+9` | 可读取设备与人才加成 |
| 开发产品 | 资金 `-10`、技术 `+6`、市场 `+7` | 需要对应技术或机会 |
| 升级仪器 | 资金 `-14` | 获得“先进仪器”，未来三次研发技术额外 `+4` |
| 招募初级人才 | 资金 `-6`、人才 `+8` | 每期运营成本 `+1` |
| 招募高级人才 | 资金 `-10`、人才 `+12` | 每期成本 `+3`，并产生股份或自主权要求 |
| 培训团队 | 资金 `-6`、人才 `+6`、技术 `+3` | 没有持续成本 |
| 扩张市场 | 资金 `-7`、市场 `+10` | 提高后续营业收入 |
| 保留现金 | 资金 `+5`、技术 `-3` | 不建立资产或机会优势 |

表中数值是行动的基础结果，不是每次执行时的固定答案。每个受影响属性都会独立获得一次整数随机修正：

```text
普通年份：最终变化 = 基础变化 + random(-5, +5)
经济危机：最终变化 = 基础变化 + random(-7, +3)
```

当前原型把 1982、2000 和 2001 视为经济危机年份。上下限均可取到。每项属性独立掷值，因此同一份订单可能回款顺利，却同时消耗更多人才；不会把整次行动简单判为“好运”或“倒霉”。

以“接普通订单”为例：

- 普通年份资金结果范围为 `+5—+15`；经济危机时为 `+3—+13`。
- 人才基础为 `-4`。普通年份可能落在 `-9—+1`，项目既可能压垮团队，也可能吸引少量熟手。
- 市场基础为 `+2`。普通年份可能落在 `-3—+7`，订单交付不再保证带来正面口碑。

普通模式选择前不显示属性名称、增减方向或随机区间，只根据选项文字做出决策；结算页再显示资金、技术、人才、市场的最终变化。确认行动时一次性生成随机修正并写入存档，刷新结果页不会重掷。开发者模式在选择前显示精确基础值与随机区间，并在结算后显示各项随机修正及对应原因文案。

随机修正同时生成一条对应属性与方向的原因文案：

| 属性 | 正向修正 | 负向修正 |
| --- | --- | --- |
| 资金 | 客户回款比预期更快。财务部短暂相信了人性。 | 客户的现金流也很紧张，于是把你的发票列入了长期规划。 |
| 人才 | 客户项目吸引来几名熟手，他们误以为交付日期只是建议。 | 交付压力赶走了几名员工，客户称这证明项目富有挑战性。 |
| 市场 | 客户的推荐带来了新订单，销售部迅速补签了功劳。 | 客户给出了诚实反馈，市场部希望下次改用匿名问卷。 |

文案解释的是随机修正本身。例如人才基础 `-4`、随机修正 `+2` 时，最终仍是人才 `-2`，但文案应描述有人被项目吸引，而不是错误地宣称人才总量上升。随机波动可以改变短期资源结果，但不能直接授予关键路线标签，也不能替代长期战略条件。

高级人才不采用额外的隐藏暴击。普通模式选择前不显示数值信息，开发者模式可用于核对波动区间、基础值与修正值。高级人才和先进仪器的研发标尺为：

```text
普通研发：技术 +9
先进仪器：技术 +13
高级人才：技术 +12
先进仪器 + 高级人才：技术 +16，并获得一次额外成果判定
```

设备预计使用两次回收投入，第三次开始形成优势。高级人才必须持续要求现金、股份或自主权中的至少一种，不能成为没有代价的永久倍率。

### 营业收入

每年基础收入由以下因素组成，并在第三次公司决策后的年报中结算：

- 基础业务收入。
- 当前市场规模。
- 隐藏声誉修正。

当前计算逻辑：

```text
能力收入 = round(((技术 + 市场) / 2) × (声誉 / 50) × 0.6)
营业收入 = max(2, 4 + 能力收入)
```

能力收入先按 `0.6` 整体折算后取整，并保证最终营业收入最低为 2。收入不再额外乘行情系数，因为行情已经在年初改变了市场值，重复乘算会把同一轮波动计算两次。

每年开始时，系统从 `0.5—1.5` 之间按 `0.1` 步长等概率生成一个行情系数，并立即写入存档。刷新页面不会重掷。市场先按该系数变化，再叠加当年的外部事件与公司决策：

```text
行情后的市场 = round(年初市场 × 行情系数)
市场变化 = 行情后的市场 - 年初市场
```

四项常驻数值仍限制在 `0—100`。行情名称按系数划分：

| 行情 | 系数范围 | 对市场的直接作用 |
| --- | ---: | --- |
| 低迷 | `0.5—0.9` | 市场收缩 |
| 平稳 | `1.0` | 市场不因行情变化 |
| 繁荣 | `1.1—1.5` | 市场扩张 |

调整后的市场直接参与营业收入计算，并通过 `0.5 + 市场 / 100` 换算成人才压力。繁荣通常扩大市场和收入，同时因市场值升高而加剧人才竞争；低迷通常压缩市场和收入，也会降低人才压力。这样形成“行情 → 市场 → 收入 → 资金”和“行情 → 市场 → 人才 → 技术”两条相互关联的经营链路。一般外部事件不指定行情；明确描述宏观周期的事件会约束随机范围：“经济学家确认衰退已经发生”为 `0.5—0.9`，“企业突然相信计算机能解决一切”为 `1.1—1.5`。

市场决定有多少潜在订单；声誉决定这些订单是否愿意相信公司。市场高而声誉低时，公司很出名，但成交和预付款能力较弱。

### 运营成本

每年固定运营成本由以下因素组成，并与同年度收入一并结算：

- 基础行政与设施费用。
- 人才规模带来的维护费用。

当前计算逻辑：

```text
人才规模成本 = round(人才 × 0.8)
运营成本 = max(0, 5 + 人才规模成本)
```

工厂、路线、合同和组织标签不会在年末额外产生收入、成本、人才或技术变化。玩家取得标签时，其数值影响已经即时结算；标签之后只作为剧情与规则条件使用，避免同一项长期影响重复计入。

### 人才与技术年度变化

年度人才与技术变化为：

```text
人才压力系数 = 0.5 + 市场 / 100
人才年度变化 = round(-5 × 人才压力系数)
技术年度变化 = round(-10 + 人才² / 250)
```

人才压力直接从年度结算时的市场值换算：市场为 `0/50/100` 时，压力系数分别为 `0.5/1/1.5`，无标签时人才变化分别为 `-3/-5/-8`。技术变化使用结算开始时的人才值计算，再与人才变化和年度净现金同时应用。人才为 `50` 且没有标签时，技术年度变化为 `0`。负数的半数按绝对值四舍五入，避免 JavaScript 默认取整使衰减偏小。

这条曲线刻意让人才产生二次增长，但 `75` 以上的被动技术收益很强，可能形成滚雪球。人才为 `0/25/50/75/100` 时，技术变化分别为 `-10/-8/0/+13/+30`。首轮先保留原公式；平衡测试必须重点观察高人才公司的技术增长，必要时通过 `talentSquaredDivisor` 或新增增长上限调整，而不是把限制写死在代码里。

### 尚未接入的周期压力

原设计中的以下周期压力暂未接入当前实现，不能与上述年度变化重复扣除：

- 基础运营从每期资金 `-8` 起步，再叠加资产与人才维护费。
- 本期没有研发或培训时，技术 `-3`。
- 本期没有开发产品、接订单或扩张市场时，市场 `-2`。
- 连续两个周期执行高强度研发或产品项目时，人才额外 `-3`。

衰减必须在行动确认前预告。它的作用是迫使玩家安排优先级，不是事后惩罚。

### 年报展示

年报把全年变化拆成四个来源：

- **当前行情**：年度行情倍率造成的市场变化。
- **外部事件变化**：当年外部事件实际生效的变化。
- **决策变化**：当年三次公司决策实际生效的累计变化。
- **经营变化**：年末公式产生的净现金、人才变化和技术变化，不包含行情造成的市场变化。
- **全年变化**：以上四部分相加后的变化。

其中资金满足：

```text
全年资金变化 = 决策资金变化 + 营业收入 - 运营成本
```

普通模式的经营结算显示：

- 当前行情及其造成的市场变化。
- 外部事件变化。
- 资金、技术、人才、市场的决策变化。
- 资金、技术、人才、市场的经营变化。
- 四部分相加后的全年变化。

开发者模式额外显示行情倍率、行情造成的市场变化、营业收入拆解、运营成本拆解、年度净现金、人才压力与人才年度变化，以及结算时人才值与技术年度变化，供调参与核对使用。

## 六、隐藏声誉

声誉范围为 `0—100`，初始值为 `50`。

普通玩家不会看到声誉总值，也不会在结算中看到具体变化幅度，只能看到 `声誉 ↑` 或 `声誉 ↓`。

以下行为通常提高声誉：

- 公开研究。
- 开放技术。
- 主动召回问题产品。
- 让核心工程师成为技术合伙人。
- 承诺中立制造。
- 保护客户设计和商业机密。
- 在危机中保护核心业务。

以下行为通常降低声誉：

- 掩盖产品事故。
- 依赖廉价且不稳定的代工。
- 拒绝核心人才并导致集体离职。
- 既替客户制造又推出竞争产品。
- 用互联网股票订单替代真实现金流。

声誉只修正经营收入，不会单独触发死亡。这样它能产生长期影响，但不会因为玩家看不到具体值而显得不公平。

## 七、开发者模式

顶部的“开发者数值”按钮默认关闭。

关闭时：

- 卡牌选择前不显示属性名称、增减方向或数值。
- 顶部不显示声誉。
- 结算只显示声誉方向。

开启时：

- 卡牌选择前显示精确数值。
- 顶部显示声誉总值。
- 经营结算显示声誉的精确变化。
- 年报显示决策变化、经营变化和全年变化；另外显示行情倍率、市场变化、收入与成本拆解、年度净现金、人才压力、人才变化和技术变化。

刷新页面后开发者模式自动关闭，避免测试设置泄漏到普通玩家体验。

## 八、事件幅度与平衡原则

剧情牌的数值幅度按事件等级控制：

| 事件等级 | 单项变化范围 |
| --- | ---: |
| 普通事件 | `±3—8` |
| 重大选择 | `±8—12` |
| 时代转折 | `±10—16` |
| 危机结算 | `±12—25` |

永久资产的即时收益应较低，但预计累计价值为 `12—20`。普通选择原则上只包含一项明显收益、一项明确成本和一个可能的长期效果，避免同时剧烈改变四项数值。

- 经营收入不能覆盖所有激进投入。
- 连续加大研发应有破产风险。
- 连续保留现金应造成技术与声誉衰退。
- 市场扩张应提高未来收入，但不能代替产品路线。
- 自有工厂提供危机优势，同时产生持续支出。
- 隐藏声誉对单期收入的影响保持温和，不能单独决定生死。
- 成功路线需要在研发、扩张和现金之间切换，而不是固定点击同一个预算。
- 每次危机至少允许三类准备方案通过，不能依赖唯一标签组合。
- 单一公司行动连续使用三次后不能仍然保持净优势。
- 随机性制造额外收益和意外，不决定一条路线能否成立。

## 九、节奏与数值验证

### 时长目标

游戏区分一次决策、一个时代、一家公司历史和完整内容体验，不把它们统称为“一局”：

| 层级 | 目标时长 | 设计用途 |
| --- | ---: | --- |
| 一次普通决策 | 10—25 秒 | 保持连续抽牌动力 |
| 一次重大决策或经营结算 | 30—90 秒 | 允许比较代价并阅读回响 |
| 一个时代 | 20—40 分钟 | 形成适合单次游玩的自然段落 |
| 一家公司完整历史 | 90—150 分钟 | 让失败后重开仍可接受 |
| 发现主要路线与结局 | 8—15 小时 | 支撑多轮游玩和长期价值 |

同一张普通卡从出现到关闭结果页，熟练玩家若平均超过 45 秒，应优先删减文字或简化信息层级，而不是加速动画。时代结束后必须允许保存退出。

### 失败节奏

- 普通年份的数值归零用于提醒玩家修正路线，不应成为大多数新玩家的首次死因。
- 三次危机是主要淘汰点，每次失败都要指出一个直接原因和两项可追溯的历史因素。
- 从时代节点重试后，玩家应在 5 分钟内遇到至少一项不同内容或不同结果。
- 不要求连续命中唯一的正确选择链；每次危机至少保留两种数值或标签组合可以通过。

### 调参指标

每轮内部测试至少记录：

- 每张卡的阅读与决策时长。
- 每个选项的选择率；长期低于 `15%` 的选项需要检查是否明显劣势或表述失真。
- 各时代入口和出口的四项数值分布。
- 首次死亡年份、直接死因与返回节点。
- 首次失败后的重试率和第二轮到达率。
- 每条路线及每种结局的达成率。
- 玩家在第二轮是否主动改变公司行动的顺序。
- 设备的平均使用次数、回本周期和购买后破产率。
- 限时机会的接受率、主动放弃率和无意过期率。

首轮平衡目标不是让随机选择也能通关，而是让认真阅读的新玩家中 `50%—70%` 到达第一次危机，首次面对危机时 `30%—50%` 生还，并能解释自己的失败。内部盲选成功率仅用于发现系统漏洞，不能代替真人测试。

新循环成立的最低信号是：玩家第二轮会主动改变“接订单、买设备、招人才、做研发”的顺序。若玩家只记住剧情牌左右答案，说明资产与机会尚未形成真正的规划空间。

### 外部参照：《Reigns》

《Reigns》的一任统治通常只承担一小段体验，死亡后通过已见卡牌、任务知识和解锁内容形成跨局进度；因此不能把“一任国王”的分钟数当作完整游戏时长。第三方 Steam 数据在 2026 年显示，其玩家总游玩时长中位数约为 2.1 小时、平均约为 3.7 小时，当前 Steam 标价为 `$2.99`。

《硅之路》不直接复制这种低价短局模型。它的参考点是快速决策、可接受的失败成本和跨轮回响；人物关系、经营结算与七十年公司历史需要更长的单轮空间。

当前定价假设用于控制内容规模，不作为最终售价承诺：

- 若最终只有 2—4 小时有效内容，且主要依靠重复卡牌，候选价为 `$5.99—7.99`。
- 若能提供 8—15 小时的差异化路线、人物回响和结局内容，候选价为 `$9.99—12.99`。
- 不以 `$2.99` 为首发目标；该价格需要远高于当前项目预期的销量规模才能支撑开发与本地化。
- 最终价格应在完整 Demo 测试后，结合愿望单质量、完成率、重玩率和同类新品价格决定；各地区价格采用 Steam 当期建议，不在设计文档中固定换算。

## 十、当前实现状态

当前 Web 原型已经实现 1960—2001 年年度回合、四类公司决策池和条件化外部事件；资产耐久与限时机会仍是后续范围。

- 完整流程为 42 个年度、168 张牌。
- 每年第三次决策先显示独立结果页，翻页后再显示当年年报，结算营业收入、运营成本与净现金，并记录到公司历史。
- 年报普通模式显示行情与四项全年变化；开发者模式额外显示行情系数、能力收入、人才规模成本、人才流动与技术演进。
- 专项预算牌只结算额外预算，避免与年度账目重复收支。
- 已实现公司行动逐属性随机修正：普通年份 `-5—+5`，经济危机 `-7—+3`；当前六次专项预算牌已使用该规则，完整九项行动池仍是后续范围。
- 三条既定成功路线仍保留在固定年份。
- 12 次读取数值并主动维护声誉的 CPU 定向流程均到达成功结局。
- 200 次完全随机流程没有成功样本，主要失败原因为资金耗尽和路线不完整。

下一步应通过真人测试调整年度卡牌的效果幅度、重复频率与单局时长，再决定是否加入资产耐久和限时机会。
